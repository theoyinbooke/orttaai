# Speech accuracy investigation — 2026-10-02

The goal is more faithful speech recognition while retaining fast dictation. The work targets the WhisperKit decoding and audio boundaries; optional language-model rewriting is outside this change.

The existing Accuracy preset started at temperature 0.2. WhisperKit samples randomly at nonzero temperature; increasing topK is not beam search. Accuracy now starts greedily at temperature 0, keeps the standard compression/log-probability/silence thresholds, and retains five quality-triggered fallback attempts. Expert overrides still take precedence. See the [pinned WhisperKit sampler](https://github.com/argmaxinc/argmax-oss-swift/blob/2870b46b92ebd522c094e4c2da77ba3c415138d8/Sources/WhisperKit/Core/Text/TokenSampler.swift) and [Whisper's fallback implementation](https://github.com/openai/whisper/blob/main/whisper/transcribe.py).

Clip commits previously split audio exactly every 15 seconds, which could split a spoken word. The change searches the final three seconds of each regular clip for a 200ms quiet gap followed by resumed speech, and splits in the middle of the latest qualifying gap. It estimates background noise from the quietest tenth of 100ms frames, scales that level by 1.8, and bounds the pause threshold between 0.005 and 0.009 RMS. The low ceiling preserves quiet endings that the 0.02 VAD threshold could treat as silence. Continuous speech keeps the 15-second boundary. Final decoding uses the same rule. Clips remain contiguous, and short remainders are folded into the preceding clip. This needs no overlap, word timestamps, model reload, or routine second transcription pass.

Pause commits now locate the end of speech with the same conservative, noise-aware threshold after establishing that the recording contains speech. Using only the 0.02 VAD threshold could commit midway through a soft final word and decode its remainder separately. The realistic corpus exposed an extra “time” after “sometime”; keeping that quiet ending with its utterance removed the duplicate. One attenuated “book” remains a recognizer miss even with its full audio retained.

A successful but empty background decode previously advanced the committed sample count even if the clip contained speech. Empty decodes now advance only over effectively silent audio; otherwise the audio stays available for recovery at finalization.

The existing live vocabulary-prompt safeguard remains in place: earlier Turbo evaluations found severe hallucinations and worse word error rates when prompts were reapplied per live clip. The existing deterministic personal-dictionary correction remains available.

## Evaluation

Baseline: repository commit cc2f269. Model: full-precision openai_whisper-large-v3-v20240930 (Large V3 Turbo). Runs use Release with testability enabled, CPU + Neural Engine, English, no vocabulary prompt, and the real production live path at the existing 4x feed pacing. The machine is an Apple M5 Max Mac Studio. Timing describes finalization after recording ends, not total CPU cost or a guarantee for another Mac.

The clean subset was selected before running the candidate: ev-001, ev-005, pn-001, pn-008, tech-001, tech-009, num-001, num-010, long-001, long-004, long-011, long-019, adv-001, adv-003, adv-006, adv-009. It spans six categories and 539 reference words. The realistic set is all 36 deterministic items generated by build_realistic_corpus.py: noisy long recordings, trailing room noise, quiet final words, quiet speech, and noise-only recordings.

The clean sample produced the following single-run comparisons. Accuracy's 73 errors fell to 29 (60.3% fewer), with median finalization 34.4% faster. Balanced's clean wording was unchanged; its median varied by 34ms while p90 increased by 42ms. Small timing differences need repeated runs before being interpreted as performance changes.

| Clean sample, 16 items / 539 words | Before WER | After WER | Before finalization p50 / p90 | After finalization p50 / p90 |
| --- | ---: | ---: | ---: | ---: |
| Balanced | 5.38% | 5.38% | 655 / 859ms | 689 / 901ms |
| Accuracy | 13.54% | 5.38% | 1060 / 1984ms | 695 / 835ms |

On the full 36-item realistic set, Balanced's normalized WER fell from **7.50% to 3.51%**: 154 word errors became 72 across 2,054 reference words (53.2% fewer). Median finalization improved from **723.5ms to 620.5ms** (14.2% faster). P90 increased from 1,141ms to 1,200ms in these single runs; the data does not establish uniformly faster tail latency. Quiet final-word recall improved from 4/6 to 5/6. Neither run contained a detected repetition loop or invented-word run. Both still produced text on two of six noise-only recordings; the attenuated “book” also remains a miss.

The [machine-readable comparison](../gauntlet/asr_eval/accuracy_update_comparison.json) records aggregate and per-item errors/timings, source hashes, and the evaluation settings. A fixed faint-floor-only pause policy was rejected because it split long noisy recordings at worse points; the noise-aware threshold restored useful boundaries while retaining quiet endings.

Validation: the final broad suite passed **671 tests, 7 skipped, 0 failed**, excluding live Codex/Grok integrations and UI automation. Regressions cover boundary padding, quiet speech, sliced audio, complete contiguous coverage, undecodable remainders, empty speech results, greedy Accuracy decoding, expert overrides, quiet words at pauses, and room-noise boundaries. The app's Top-K help now explains that it applies when Temperature is above zero.

These corpora originate from synthetic speech. They can detect regressions and compare this change, but do not establish accuracy for a particular speaker's accent or microphone. A consented, human-transcribed real-voice set is the next useful benchmark.

To reproduce, generate the realistic corpus with `python3 gauntlet/asr_eval/build_realistic_corpus.py`, then run `gauntlet/asr_eval/run_eval.sh` with `ORTTAAI_ASR_EVAL_MODEL=openai_whisper-large-v3-v20240930`, `ORTTAAI_ASR_EVAL_MODEL_ROOT` set to the existing local model-storage base, `ORTTAAI_ASR_EVAL_PATHS=live`, and the chosen preset/manifest/IDs. Use `ORTTAAI_EVAL_CONFIG=Release` and `ORTTAAI_EVAL_XCODEBUILD_EXTRA='-derivedDataPath .build/accuracy CODE_SIGNING_ALLOWED=NO'` for the inert XCTest host. Score with `score.py`; pass `--manifest gauntlet/asr_eval/corpus_realistic/manifest_realistic.json` for the generated set. Baseline and candidate must use the same corpus, model, pacing, and scorer, with no concurrent builds or model workloads during timed runs.
